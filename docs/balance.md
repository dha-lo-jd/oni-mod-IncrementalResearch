# バランス調整の方針と根拠

見た目の数値は指数的に増え、実際の進行はプレイ時間に対して(対数スケールで)直線的に進む、という設計の記録。
計算は `tools/balance_sim.py`(最善手のシミュレータ。ゲームには含まれない)で行った。定数は `Core/KnowledgeRules.cs`。

## 起きていた問題

パラダイムシフトを連続で繰り返すと、シフトの周期がどんどん短くなり、知見の増加量が数分のうちに無限に至った。

原因は、MIが何重にも効いていたこと。

- MI倍率が、第1階層の生産だけでなく、第2・第3階層の積み上げ速度にも掛かっていた(上位階層の積み上げは時間の2〜3乗で伸びるので、MI倍率が3〜4回かかる)。
- 獲得MIは T^0.5、倍率は MI に比例。周期が短くなるほど、1周期で得られるMIが累計を上回り、周期がさらに短くなる(有限時間での発散)。

## 設計の考え方

最善手では、1周期の長さ D がほぼ一定で、周期ごとに生産量が一定倍になれば、「生産量の対数が時間に比例する」。
そのためには、獲得MIの指数 p とMI倍率の指数 q が、p × q ≒ 1 に近い必要がある。

- p × q > 1: 周期が縮み続ける(暴走)。
- p × q < 1: 周期が延び続ける(失速)。

周期内の生産は、拡張と積み上げで時間の高次(約5乗)で伸びるため、周期の長さは MI の大きさにほとんど依存しない。
これを使い、p と q を 1 に近づけ、そこから漸減させる、という方針にした。

## 採用した形

- 獲得MI = floor( 10 ^ ( p0 × lg x − c × (lg x)² ) )、x = T / T0。T0 = 1e14、p0 = 0.98、c = 1e-4。
- MI倍率 = 1 + v。v = kM を、1 を超えたところから 10 ^ ( lg(kM) − c_m × (lg(kM))² ) に漸減。k = 0.01 + 0.0005 × (MIの拡張回数)、c_m = 5e-5。
- MI倍率を上位階層の積み上げ速度には掛けない。
- 実効ベース率 = 8 × (S / 8)^0.5(S は実測のベース率)。研究産出の多いコロニーほど速くなるが、比例ではなく平方根にして差を縮める。

## 結果(S = 8、最善手に近い方針: 獲得MIが max(累計MI, 1/k) の4倍になったらシフト)

| 経過 | 周期 | log10(生産量) |
| --- | --- | --- |
| 初回のシフト | 約 1.75 時間 | |
| 10 時間 | 約 52 分 | 約 19 |
| 25 時間 | 約 23 分 | 約 40 |
| 50 時間 | 約 27 分 | 約 89 |
| 100 時間 | 約 85 分 | 約 134 |
| 400 時間 | 約 10 時間 | 約 184 |

- 10〜100 時間は、1 時間あたり約 1〜2 桁(対数スケールで直線)。100 時間を過ぎるとゆるやかに失速し、400 時間でも無限に達しない。
- ベース率 S が 2〜32(16倍)のとき、初回のシフトは約 3.5 時間〜約 0.9 時間、傾きは約 1〜4 桁/時間。
- この数値は、モデル(購入は安い順、設備は常時稼働、S は一定)による目安。実機のペースは、実際に遊んで合わせる。

## 再調整するには

`tools/balance_sim.py` の `make3` の引数(T0、k、p0、c、c_m)と `Params` の定数を、ゲーム側の定数と揃えて変える。
目安: 初回のシフトが遅すぎれば T0 を下げる、周期が短すぎれば k を下げる、失速が早すぎれば c と c_m を下げる。
