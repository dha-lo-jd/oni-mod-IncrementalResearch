# 知見と1階層目施設(記録保管庫)の仕様

[concept.md](concept.md) の「通貨と生産の階層」「上位設備とバニラ側クエスト」を実装可能な粒度に落とした仕様。
既存の研究設備群(研究ステーション、スーパーコンピューター、原子力研究ステーションなど)を0階層目とし、記録保管庫を1階層目とする。

数値は初期値で、バランス調整のため定数にまとめる(「調整可」と書いたもの)。

## 用語

階層ごとの話とゲーム全体の話で、呼び方を使い分ける。

- **拡張**: 知見を払って階層の設備を強化する操作。UI の文言は「設備を拡張して[固有単位名]を増やす」とする。
- **拡張段階(数)**: ゲーム全体の説明や共通のUI、設計書での呼び名。構想ドキュメントの「研究規模(スケール値)」にあたる。
- **固有単位名**: 設備ごとのフレーバー名。設備の画面、ツールチップ、通知など、その設備について話す場面で使う。

| 階層 | 設備 | 固有単位名 |
| --- | --- | --- |
| 1 | 記録保管庫 | 収蔵量 |
| 2 | 計算機室 | 演算ノード数 |
| 3 | 真空実験室 | 実験系統数 |

- 値の意味は共通で、「生産量が比例する、知見で買う加算値」である。固有単位名は表示上の名前にとどめ、計算式は階層間で共通に扱う。
- 実装では、階層の定義に固有単位名の `LocString` を持たせ、共通UIは「拡張段階」の文言を使う。
- 設計書では、階層を特定しない説明は「拡張段階」、階層ごとの説明は固有単位名を使う。

## 1. 知見

### 保持
- コロニー全体で1つ(SaveGame単位)。`ISaveLoadable` を持つ KMonoBehaviour の単一インスタンスに、知見、拡張段階、各階層の状態を保存する。
- 知見の量は、1000分の1を最小単位とする整数(`BigInteger`)で保持し、表示のときだけ 1000 で割る。小数は切り捨て、1回の更新で出た端数は次の更新に持ち越す。将来、巨大な数を扱っても、浮動小数点の誤差や桁あふれが起きないようにするため。セーブには文字列で保存する。
- 土台の速度(研究ポイント/秒)は割合の値なので `double` のままにする。
- 表示は、1e6 以上を科学表記にする。
- ゲーム内時間(`dt`)で進む。ゲームを閉じている間は進まない。

### 土台 S(知見/秒の基礎値)
- 0階層目の研究設備で複製人間が行った研究の実績から決める。
  - ステーションが生んだ研究ポイント(`ResearchCenter.ConvertMassToResearchPoints` が `Research.AddResearchPoints` に渡す値)を、種類(`research_point_type_id`)ごとに集計する。
  - 腕前(`AttributeConverters.ResearchSpeed`)は、研究ポイントの生産量に既に反映されているので、別に掛けない。
- S は直近の集計の指数移動平均(時定数 1サイクル=600秒、調整可)の「研究ポイント/秒」とし、種類ごとの重みを掛けて合算する。
  - 重みの初期値: basic=1、advanced=2、それ以外は未使用(調整可)。
- 研究が止まれば S も下がり、知見の伸びも落ちる(コロニーが供給する土台、という構想どおり)。

### 研究完了後の遊休運転
- バニラの研究設備は、研究ツリーを完了すると稼働しない(`ResearchCenter.UpdateWorkingState` が `!IsAllResearchComplete()` を条件にしている)。また、アクティブな研究がないと `Research.AddResearchPoints` は何もしない。
- そのため、記録保管庫が1台でもコロニーにあり稼働中のとき、研究設備を「遊休運転」に切り替える。
  - 研究設備は通常どおり原料(土、水など)を消費し、作業を行う。
  - 生まれた研究ポイントは `Research` には渡さず、土台の集計にだけ加える。
- 記録保管庫がない、または止まっているときは、バニラの動作のままにする。

### 知見の消費と生産
- 1階層目の知見生産量(知見/秒) = S × 収蔵量 × 倍率 m1。
  - 収蔵量 = 1 + 拡張回数 n1。設備を建てた時点で収蔵量は1で、拡張で増える(拡張0回でも知見が貯まり、最初の拡張費用に届く)。
  - m1 の初期値は 1.0。パラダイムシフト実装後は、パラダイム通貨による倍率をここに掛ける。
- 拡張回数 n1 は、知見を払って1ずつ上げる。コスト c(n) = 10 × 1.15^n(調整可)。
  - 連続購入(×10 など)は UI の実装時に決める。
- 記録保管庫が稼働していないあいだは、1階層目の生産量は 0。購入済みの拡張段階は失われない。

## 2. 記録保管庫(1階層目)

| 項目 | 内容 |
| --- | --- |
| 建物ID | `IR_RecordArchive`(名称: 記録保管庫) |
| サイズ | 3×3、床置き(`BuildLocationRule.OnFloor`) |
| 建設素材 | 金属素材1種。質量は `TUNING.BUILDINGS.CONSTRUCTION_MASS_KG` の中位(TIER3 か TIER4)から実装時に決める |
| 電力 | 稼働時 120W(スーパーコンピューターと同程度) |
| 発熱 | `SelfHeatKilowattsWhenActive` = 1.0 kDTU/s(調整可) |
| 作業者 | 不要。複製人間は立ち入らない |
| 部屋 | 研究設備と同じ部屋に置く必要はない。`ScienceBuilding` タグは付けない(研究室の判定に影響させない) |
| 設置数 | コロニー全体で1台まで |
| 稼働条件 | 電力が供給されていること。それ以外の環境条件は課さない |
| 解禁 | 研究ツリーの全完了後。開発中は設定で即時解禁にできるようにする |

### 設置数の制限
- 建築時の判定(`BuildingDef.IsValidPlaceLocation` の Postfix など)で、既に記録保管庫が存在する場合は置けないようにする。
- 構想の「各階層1台を建てる。台数の役割は拡張段階が担う」に対応する。

### 解禁
- 研究ツリーの全完了(`Research.Instance` の全技術が購入済み)を検知して、建築メニューに表示する。
- 建築メニューへの追加は `ModUtil.AddBuildingToPlanScreen`、表示の切り替えは建物定義の `ShowInBuildMenu` で行う想定。実装時に動作確認する。

### 次の階層(計算機室)の解禁
- 放置ゲーム側: n1 が閾値に達すると設計図が解禁される。閾値は初期値 25(調整可)。
- バニラ側: 設備を建てて環境(鋼鉄、冷却)を整える。仕様は別途。

## 3. 実装の順序

1. **基盤**: 状態クラス(知見、拡張段階)、セーブ・ロード、`dt` による更新。デバッグ用に知見を足すコマンド。
2. **土台の集計**: `ResearchCenter.ConvertMassToResearchPoints` の Harmony パッチで、種類ごとの研究ポイントを集計し、S を求める。
3. **記録保管庫**: 建物定義、設置数制限、解禁、稼働条件(電力)、翻訳(`STRINGS`、`ja.po`)。
4. **遊休運転**: 研究完了後も研究設備を稼働させる。
5. **購入と表示**: 拡張段階の購入、研究画面の簡易な表示(知見、S、n1、生産量)。

## 4. 確認が必要な点

- 遊休運転の実装方法。`ResearchCenter.UpdateWorkingState` の条件を差し替えるパッチで足りるか、`IsAllResearchComplete` をパッチする方がよいか。実装時に検証する。
- 重みや時定数、コスト曲線の妥当性。実際に遊んで調整する。
- スーパーコンピューター等が複数あるときに、土台が大きくなりすぎないか(原料消費で自然に抑えられる想定)。
