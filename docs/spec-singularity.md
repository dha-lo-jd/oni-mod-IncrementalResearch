# シンギュラリティと臨界定数(CC)の仕様

放置ゲームの上位の転生と、その通貨の仕様。構想は docs/concept.md、拡張と自動購入の分類は docs/spec-upgrades.md を参照。

**実装済み(未検証)。** 数値は仮で、ゲーム内で調整する。本編向けの報酬(属性ボーナス、興味関心の付与)は、この仕様の範囲外で、別途実装する。

## 発動条件

次の3つをすべて満たしたとき、知見タブの「シンギュラリティ」ボタンが押せる。

1. 最後の階層(第7階層)の設備の設計図を解禁している。
2. 最後の階層(第7階層)の拡張を、いまの周回で45回行っている(`KnowledgeRules.SingularityMinTopExpansions`)。パラダイムシフトでリセットされるので、連続でシフトしても満たせない。
3. 自動拡張のアップグレード(第1〜7階層)をすべて買っている。
4. 記録保管庫に、必要な数のデータバンクが納品されている。

データバンクは、バニラのアイテム(`DatabankHelper.TAG`)をそのまま使う。複製人間が運び込む。

- 納品口: 記録保管庫に `Storage` と `ManualDeliveryKG` を足した。新しい建物は作らない。
- 必要数: n回目(0から数える)のシンギュラリティに `10 + 2n` 個、上限60個(10、12、14、…、25回目以降は60個)。増え方は緩やかにして、高速周回でも無理が出にくくする。
- 運び込みを頼むのは、第7階層の設計図の解禁後(シンギュラリティが見えている間)だけで、頼む量は必要数まで。
- 納品されたデータバンクは、シンギュラリティで必要数だけ消費する。
- データバンクはベースゲームでも入手できるため、代替の納品物は要らない。

## リセットと残るもの

- リセットする: 知見、メタ知見、それらで買った拡張とアップグレード(自動化を含む)、パラダイムシフトの回数、学派、各階層の設計図の解禁。
- 残る: 臨界定数、CCの拡張、CCで買ったアップグレード、自動化のオンオフ、チュートリアルの既読。建てた設備は何も変わらない。
- 設計図の解禁が戻るので、次のシンギュラリティにも、もう一度第7階層までの解禁、第7階層の拡張45回、自動拡張の購入し直しが要る。

## 臨界定数(CC)

- 獲得: そのときの周回のMI累計の対数。`(floor(log10(MI累計)) - 5)` を最低1・最大10にして5倍した CC(`KnowledgeRules.CcGain`)。いまの周回で約15 CC。シフトをもう1回重ねるとMIが約5倍になり、獲得量は約+0.7。待てば少し増えるが、対数と上限で伸びを抑える。CCを際限なく増やせないための歯止めは、この対数と上限、報酬の二次曲線のコスト。
- 表示: 数字の横に「CC」。説明文は「シンギュラリティで確定した定数。液体ではない。」(docs/terminology.md)。

### CCの拡張

2種類あり、それぞれ別に買う。コストは `ceil(2 × 1.6^買った回数)` CC。

| 拡張 | 効果 |
| --- | --- |
| 生産の定数 | 全階層の生産倍率に、n個目(0から数える)が ×(1 + 0.7×0.8^n)。累計は3個で×3.8、8個で×11、12個で×15.6、上限は約×19.8。上限が、1周の下限(約30分)を決める |
| メタ知見の定数 | パラダイムシフトで得るメタ知見に、n個目が ×(1 + 0.35×0.8^n)。上限は約×4.4 |

生産の倍率は、第1階層の生産(階層同士の積み上げは対象外。メタ知見の倍率と同様に、積み上げの暴走を避けるため)に掛かる。

### CCで買うアップグレード(自動化)

どれも、シンギュラリティを1回行うと買えるようになる。

| id | 名前 | CC | 効果 |
| --- | --- | --- | --- |
| C_AUTO_SHIFT | 自動パラダイムシフト | 10 | 得られるメタ知見が、これまでの獲得量(累計)の設定した割合に達したら、自動でシフトする。割合は入力欄で変えられる(初期値25%、1〜9999%)。学派は今のまま |
| C_AUTO_MI_UPGRADE | 購入の委任 | 3 | 買えるメタ知見のアップグレードを自動で購入する |
| C_AUTO_EXPAND | 定数の自動調整 | 3 | 買えるときにCCの拡張を自動で購入する(安い方から) |

自動化は、知見タブの「自動化」セクションでオンオフを切り替えられる(他の自動購入と同じ)。

## UI

- 知見タブの、パラダイムシフトの下に「シンギュラリティ」の枠を足した。第7階層の設計図を解禁するまでは見えない。
- 枠の中身: 回数とCC、CCの説明、条件(第7階層の拡張数と自動拡張の購入数)、納品数(納品済み/必要数)、シンギュラリティのボタン、CCの拡張2つ。
- ボタンを押すと確認ダイアログ(得るCC、消費するデータバンク、リセットされるもの、残るもの)が出る。
- CCのアップグレードは、知見のアップグレード一覧に、購入ボタン「購入(CC n)」つきで並ぶ。
- チュートリアルの第13段階(シンギュラリティが視野に入ったとき)を足した。
- デバッグモードの行に「+5 CC」を足した。

## 確認すること(ゲーム内)

- 記録保管庫にデータバンクが運び込まれ、納品数が増える。
- シンギュラリティで、データバンクの消費、リセット、CCの加算が仕様どおりに行われる。セーブ・ロードで保たれる。
- 生産の定数が生産に、メタ知見の定数がシフトの獲得量に効く。
- 自動パラダイムシフトの間隔が適切か(初期値25%)。入力欄で数値を打てるか、打っている間にゲームのホットキーが反応しないか。
- 数値の調整(必要数、CCの獲得量、拡張の倍率とコスト、自動化のコスト)。

## シミュレータでの確認
`SING=1 python tools/balance_sim.py 8 60 7` で、シンギュラリティまで含めて試算できる(データバンクは納品済みと仮定)。
- 1回目のシンギュラリティは約6.8時間(CCの拡張がまだ無いので変わらない)。条件を満たすまでのシフトは9回。
- 2回目以降の1周は、2.4h → 1.6h → 1.0h → 0.8h → 0.7h → 0.6h と縮み、25回目あたり(累計約30時間)で約30分に収束する。生産の定数の上限(約×19.8)が、1周の下限を決める。
- 1周の長さは、生産の定数の上限で決まる(上限×10で約42分、×30で約19分、×60で約12分)。上限を上げるときは下限が下がることに注意する。学派はシミュレータに入っていないので、実際はこれより少し短くなる可能性がある。
- 第7階層の拡張45回の目安は、最善プレイでシフト9〜10回目の周回の終わりに当たる。
