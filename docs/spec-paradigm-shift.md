# パラダイムシフトの仕様

[concept.md](concept.md) の「パラダイムシフト」を実装可能な粒度に落とした仕様。
拡張とアップグレードの仕様は [spec-upgrades.md](spec-upgrades.md)、知見の仕様は [spec-knowledge-tier1.md](spec-knowledge-tier1.md) を参照。
数値は初期値で、バランス調整のため定数にまとめる(「調整可」と書いたもの)。

## 概要

- パラダイムシフトは、知見の側をリセットして、メタ知見(MI)を得る周回操作。繰り返すことを前提とする。
- MIは、生産への倍率、MIの拡張、MIのアップグレードに使う。本編向け報酬の購入には使えない。
- 一定回数を重ねると、シフトごとに方針を選ぶ「学派」が解禁される。

## 実行できる条件

- そのシフトで得られるMIが1以上になったら、いつでも実行できる。
- 早く回すか、待ってMIを増やすかは、プレイヤーが決める。
- 実行の前に確認ダイアログを出し、「得られるMI」と「失うもの」を示す。

## MIの獲得量

- そのシフトの間に生産した知見の累計(支払った分も含む)を T とする。
- 獲得MI = floor( (T / T0) ^ p )。T0 の初期値は 100,000(知見)、p の初期値は 0.5(いずれも調整可)。
  - 例: T = 10万で 1、100万で 3、1億で 31。待つほど増えるが、効率は落ちる。
- T は、シフトのたびに0に戻す。保持は `BigInteger` で、セーブには文字列で保存する(知見と同じ方針)。
- MIは1単位が最小の整数で、1000分の1の固定小数点にはしない。

## リセットするもの、残すもの

| 項目 | パラダイムシフトで |
| --- | --- |
| 知見 | リセット |
| 知見の拡張(拡張段階) | リセット |
| 知見で買ったアップグレード | リセット |
| ベース率 S(研究ポイントの移動平均) | 残す(コロニーの実測値で、放置ゲームの数字ではない) |
| MI、MIの拡張、MIで買ったアップグレード | 残す |
| 学派の選択 | シフトの際に選び直す |
| チュートリアルの進行 | 残す |

- バニラ側の建物や環境には、一切触れない(構想の共通方針)。
- シフトの直後は、記録保管庫が稼働していれば、拡張0回(収蔵量1)から知見が再び貯まり始める。

## MIの使い道

### 1. 生産への倍率

- 全生産に、MI倍率 m_MI を掛ける。m_MI = 1 + k × (累計獲得MI)。k の初期値は 0.1(調整可)。MIの拡張で k が増える(下記)。
- 倍率の元は「累計獲得MI」で、MIを使って減らない。使うと倍率が下がる設計にすると、買い物と倍率が競合してしまうため。
- 生産量の式は、[spec-upgrades.md](spec-upgrades.md) の m_t に m_MI を掛ける。

### 2. メタ知見の拡張

- MIで買う拡張。繰り返し買え、コストは指数的に増える。
- 効果: 拡張1回ごとに、MI倍率の係数 k を 0.02 増やす(初期値、調整可)。
- コスト: 3 × 1.5^n MI(n は拡張回数。調整可)。
- 固有単位名(仮): 理論数。UI は「設備を拡張して〜」とは別に、「理論を積んで理論数を増やす」のような言い回しにする。
- 保持はパラダイムシフトで残る。

### 3. メタ知見のアップグレード

- MIで買う単発購入。仕組みは [spec-upgrades.md](spec-upgrades.md) と共通で、通貨が MetaInsight になる。
- 初期案:

| id | 名前案 | 効果 | コスト(MI) | 解禁条件 |
| --- | --- | --- | --- | --- |
| M_HEADSTART | 蓄積された基礎 | シフト後の初期知見 +100 | 3 | シフト1回 |
| M_DISCOUNT | 索引の継承 | 知見の拡張の基準コスト ×0.5 | 8 | シフト2回 |
| M_AUTO_UPGRADE | 購入の定型化 | 知見で買うアップグレードの自動購入を解放(解放にMIを使う) | 20 | シフト3回 |

- 「アップグレードの自動購入は、一つ上位の通貨で買う」という確定済みの規則に従い、上の自動購入は MI で買う。
- 拡張の自動購入のアップグレード(知見の拡張はT1_AUTO_EXPAND、メタ知見の拡張はM_AUTO_EXPAND)も、[spec-upgrades.md](spec-upgrades.md) の規則に従う。知見の拡張の自動購入はシフトでリセットしない。

## 学派

- シフトを重ねたあとに解禁される。最初から出さず、何度か繰り返して慣れてきた頃に出す。
- 解禁条件: パラダイムシフトを累計 5 回実行したとき(調整可)。解禁時に、短い説明ダイアログを一度だけ出す。
- シフトを実行するたびに、学派を1つ選ぶ。選んだ学派は、次のシフトまで続く。選ばなくてもよい(無所属)。
- 学派は、階層ごとの生産に補正を掛ける。補正は、倍率の積の一項として、`基礎倍率 × 学派補正` の形で書く。
- 初期案(階層が増えたときに意味を持つ。数値は調整前提):

| 学派 | 効果 |
| --- | --- |
| 実験主義 | 下位階層(1〜2)の生産 ×1.5、上位階層(3以降)の生産 ×0.8 |
| 理論主義 | 上位階層(3以降)の生産 ×1.5、下位階層(1〜2)の生産 ×0.8 |
| 体系主義 | 全階層の生産 ×1.2 |

- 現状は第1階層だけなので、実際に効くのは実験主義(×1.5)、理論主義(×0.8)、体系主義(×1.2)。階層が増えたときに見直す。

## 保存するデータ

`KnowledgeState` に追加する。

- 今回のシフトでの知見の累計 T(`BigInteger`、文字列で保存)。
- MI(`BigInteger`)と累計獲得MI(`BigInteger`)。
- MIの拡張回数、MIで買ったアップグレードの id 集合。
- パラダイムシフトの累計回数。
- 選択中の学派 id。

## UI

- 知見タブに「パラダイムシフト」のセクションを足す。実行できるようになったら、「得られるMI」と実行ボタンを出す。
- 実行ボタンを押すと確認ダイアログ(得られるMI、リセットされるもの、残るもの)を出し、学派が解禁済みなら、そこで学派を選ぶ。
- 知見タブに、所持MIと累計獲得MI、現在のMI倍率を表示する。MIの拡張とアップグレードの一覧も同じタブに置く。
- 主画面の知見の表示は、MIを持っているときだけ「MI: n」を併記する。控えめな表示にする(MIは冗談として扱わない、という既存の方針)。
- チュートリアルに、MIが初めて獲得できるようになったときの段階を足す。

## 実装の順

1. 状態: T の積算、MI と累計獲得MI、シフトの実行、リセット、m_MI の計算。生産量の式に m_MI を組み込む。
2. 知見タブのシフトのセクションと確認ダイアログ、主画面の表示、チュートリアルの段階、`STRINGS.cs` と `translations/ja.po`。
3. MIの拡張とMIのアップグレード(定義の仕組みは [spec-upgrades.md](spec-upgrades.md) と共通)。
4. 学派(解禁条件、選択UI、補正の計算)。

## 確認する点

- 条件を満たしたらシフトでき、リセット後に知見・拡張・知見のアップグレードが初期化され、MIとMIの拡張・アップグレードが残る。
- シフト後、MI倍率で生産量が増える(主画面の +x/秒)。
- セーブとロードで、MI・累計・シフト回数が保たれる。
- 巨大な値になっても、表示が崩れない。

## 未確定

- (解決済み)拡張の自動購入のアップグレードは、シフトでリセットしない。
- T0、p、k、拡張のコスト曲線、学派の補正の数値。実際に遊んで調整する。
- 学派の追加(階層が増えたとき)と、学派を解禁後に変える頻度。
