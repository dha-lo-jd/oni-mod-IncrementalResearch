# 設備アップグレードの仕様

[spec-knowledge-tier1.md](spec-knowledge-tier1.md) の「拡張」に加える、倍率・効果を足す単発購入の仕様。
数値は初期値で、バランス調整のため定数にまとめる(「調整可」と書いたもの)。

## 位置づけ

- **拡張**: 階層ごとの量(収蔵量など)を1ずつ増やす。何度でも買え、コストは指数的に増える。
- **アップグレード**: 倍率や効果を足す。1つにつき1回だけ買える単発購入。
- どちらも知見で買う。同じ通貨で競合するので、「拡張を進めるか、アップグレードを買うか」の選択が生まれる。

## 定義

アップグレードはデータ駆動の定義(`UpgradeDef`)として持つ。

| 項目 | 内容 |
| --- | --- |
| id | 一意の文字列。セーブにはこれを保存する |
| 範囲 | 施設(階層を指定)または全体 |
| 通貨 | 知見またはメタ知見(MI) |
| コスト | 固定の整数(`BigInteger`、知見は1000分の1単位) |
| 効果 | 下の種別と値 |
| 解禁条件 | その階層の拡張回数、他のアップグレードの購入、またはその両方 |

効果の種別:

- `ProductionMultiplier`: その範囲の生産量に値を掛ける。
- `ExpansionCostGrowth`: 拡張コストの成長率を置き換える。
- `ExpansionCostMultiplier`: 拡張コストの基準値に値を掛ける。
- `Convenience`: まとめ買いなど、操作の手間を減らす機能を解放する。

### 保存と表示

- 購入済みは id の集合として `KnowledgeState` に保存する(文字列で持つ)。
- 解禁条件を満たすまでは非表示。満たしたら、買えるかどうかによらず表示する(次の目標が見えるように)。
- 購入済みは一覧の下に折りたたむ。

## 生産量と拡張コスト

- 階層 t の知見生産量 = S × 収蔵量_t × m_t(S は研究ポイントの移動平均、収蔵量は固有単位名の値)。
- m_t = その階層の施設アップグレードの積 × 全体アップグレードの積 × MI由来の倍率(パラダイムシフト実装後)。
- 拡張コスト c(n) = 基準コスト × 成長率^n。基準コストの初期値は 10、成長率は 1.15(いずれも調整可)。アップグレードで変えられるよう、`KnowledgeRules.ExpansionCost` は状態を受け取る形にする。

## 1階層目(記録保管庫)の知見アップグレード

| id | 名前案 | 効果 | コスト | 解禁条件 |
| --- | --- | --- | --- | --- |
| T1_INDEX | 索引の整備 | 生産 ×2 | 50 | 拡張3回 |
| T1_CLASSIFY | 分類体系 | 生産 ×2 | 1,000 | 拡張15回、T1_INDEX |
| T1_CROSSREF | 相互参照 | 生産 ×3 | 20,000 | 拡張30回、T1_CLASSIFY |
| T1_SHELVING | 書架の効率化 | 拡張の成長率を 1.15 から 1.13 に | 500 | 拡張10回 |
| T1_BULK | 一括拡張 | 拡張ボタンに「×10」「最大」を追加 | 300 | 拡張5回 |

- コストの目安: 拡張コストは n=15 で約81、n=30 で約660、n=50 で約1.1万。アップグレードは同じ段階の拡張コストの数倍から10倍に置く。
- 名前と数値は仮。実際に遊んで調整する。

## 全体アップグレード

- 全階層の生産に効く。ただし、同じコスト帯の施設アップグレードより効果の係数を弱くする(施設版が ×2 なら全体版は ×1.5 など)。設備単独で見ると効率が落ちる、という位置づけ。
- 全階層に掛かるので、階層が増えるほど総効果が施設アップグレードを上回る。階層が1つの間は施設版のほうが得で、第2階層以降で逆転する。
- 初期案:

| id | 名前案 | 効果 | コスト | 解禁条件 |
| --- | --- | --- | --- | --- |
| G_NETWORK | 記録網 | 全階層の生産 ×1.5 | 5,000 | 記録保管庫の拡張20回 |

- 階層が実装されるまでは第1階層にしか効かない。説明文でそのことを示す。

## メタ知見(MI)のアップグレード

- 通貨と定義の仕組みは知見のものと共通にし、`通貨 = MetaInsight` の定義として足す。
- 内容、リセットの扱い、MIの獲得と使い道は [spec-paradigm-shift.md](spec-paradigm-shift.md) を参照。
- MIは本編向け報酬の購入には使えない(既存の方針どおり)。

## 拡張の種類と自動購入

### 拡張は3種類

拡張は、買う通貨ごとに3種類ある。

| 種類 | 通貨 | リセット(案) |
| --- | --- | --- |
| 知見の拡張 | 知見 | パラダイムシフトでリセット |
| メタ知見の拡張 | MI | パラダイムシフトでは残り、シンギュラリティでリセット |
| CCの拡張 | CC | シンギュラリティでも残る |

- これまでの階層ごとの拡張(収蔵量など)は、知見の拡張にあたる。
- メタ知見の拡張とCCの拡張が何を増やすかは、パラダイムシフトとシンギュラリティの仕様を決めるときに決める。

### 自動購入のアップグレード

- 自動購入は、専用のアップグレードを買って解放する。拡張の種類ごとに、それぞれ別のアップグレードを設ける(知見の拡張の自動購入、メタ知見の拡張の自動購入、CCの拡張の自動購入)。
- **拡張の自動購入**は、その拡張と同じ通貨で購入する。
  - 知見の拡張の自動購入は知見、メタ知見の拡張の自動購入はMI、CCの拡張の自動購入はCCで買う。
  - 解放後は、条件を満たす間、その通貨で拡張を自動で買う。
  - 構想にあった「拡張の自動購入はCCの用途」という方針は、この仕様で置き換える。
- **アップグレードの自動購入**は、そのアップグレードを買う通貨より一つ上位の通貨で購入する。
  - 知見で買うアップグレードの自動購入は、MIで買う。
  - MIで買うアップグレードの自動購入は、CCで買う。
  - 上位の通貨がないため、CCで買うアップグレードの自動購入は存在しない。
- 通貨の順序は、知見、MI、CC の順に上位とする。
- 一括拡張(×10、最大)や、買えるアップグレードの通知のような手間の軽減は、自動購入とは別の通常のアップグレードとして扱う。

### 未確定

- 「アップグレードの自動購入」を、解放に一つ上位の通貨が要ると読んでいる。解放後に自動で買うときの支払いは、そのアップグレードの本来の通貨とする。支払いごと上位通貨にする意図なら、見直す。
- 自動購入の対象の優先順位(安い順など)、ON/OFF の切り替え、購入の間隔。
- CCの拡張とCCで買うアップグレードの内容。

## UI

- 研究画面の知見タブに「アップグレード」の一覧を追加する。1行に、名前、効果、コスト、購入ボタンを並べる。
- 記録保管庫のサイドパネルは、これまでどおり拡張ボタンを置く。買えるアップグレードがあるときだけ、件数を1行足す。
- 主画面の知見の表示は変えない。
- チュートリアルに、最初のアップグレードが買えるようになったときの第4段階を足す(文言は実装時に決める)。

## 実装の順

1. 基盤: `Core/UpgradeDef.cs`(定義と一覧)、`KnowledgeState` に購入済みの集合、購入処理、倍率とコストの計算を足す。
2. UI: 知見タブの一覧、`STRINGS.cs` と `translations/ja.po`。
3. 動作確認。
4. MIのアップグレードは、パラダイムシフトの実装時に足す。

## 確認する点

- 購入後に、生産量(主画面の +x/秒)と拡張コストが仕様どおりに変わる。
- セーブとロードで購入済みが保たれる。
- アップグレードを持たない既存のセーブが壊れない。
